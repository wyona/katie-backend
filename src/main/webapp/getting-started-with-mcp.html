Getting started with Katie as MCP (Model Context Protocol) server

Katie can be used as MCP server with the URL https://app.katie.qa/mcp respectively when running it locally at http://localhost:8044/mcp

In order to access a particular Katie domain one has to create an access token:

  • https://app.katie.qa/swagger-ui/index.html#/Authentication Controller v1/generateGenericJWT
  • Request body, whereas replace the domain id (did) below: 
    {
  "privateClaims": {
    "did": "20275809-8c17-4f3d-a3f7-0657c1435e54",
    "scope":"search",
    "endpoint":"/mcp"
  }
}
  • Set access token inside MCP client (e.g., npx @modelcontextprotocol/inspector@0.16.8), whereas this access token does only allow to query "public" domains, where answers are not generally protected, because the token does not contain a particular user / domain member.

OAuth 2.0 Flow

  • Configure OAuth inside your MCP client (Client OD, Redirect URL, Scope)
  • The MCP client will send a request (/mcp) to Katie and if it replies with 401, then the MCP client will send an OAuth authorize request to Katie (https://app.katie.qa/swagger-ui/index.html#/OAuth%20Controller%20v1/authorize)
  • Katie will redirect the client to the authentication server, e.g., Google (https://accounts.google.com/o/oauth2/v2/auth), Microsoft, ...
  • When the client could authenticate itself and got redirected back to itself, then the MCP client will ask Katie for an access token (https://app.katie.qa/swagger-ui/index.html#/OAuth%20Controller%20v1/getToken)
  • The MCP client will use the received access token to access Katie MCP at /mcp
